## 4.3 명시적 강제변환

### ***이상한 나라의 틸드(~)***

- -1 이 나오는 결과를 falsy로 만들어주는 연산자 `~`
- `~` 연산자는 먼저 32비트 숫자로 ‘강제변환’한 후 `NOT` 연산을 한다. (각 비트를 거꾸로 뒤집는다)
- `~` 는 2의 보수를 구한다. ⇒ `~x` 는 대략 `-(x+1)` 과 같다.
    - 🔧 먼저, `~x`는 무슨 뜻인가?
    - `~x`는 **비트 NOT 연산자**로, x의 모든 비트를 뒤집어.
    - 예: `x = 5` → 이진수: `00000000 00000000 00000000 00000101`
    - `~x` → `11111111 11111111 11111111 11111010` → 이건 -6이야.
    - 🧠 왜 `~x === -(x + 1)`이 되는가?
        
        자바스크립트는 내부적으로 **32비트 정수**를 사용해서 비트 연산을 처리해. 이때 음수는 **2의 보수**로 표현예제: `x = 5`
        
        1. `x = 5` → 이진수: `00000000 00000000 00000000 00000101`
        2. `~x` → 비트 반전: `11111111 11111111 11111111 11111010`
        3. 이 값은 2의 보수로 표현된 -6이야.
        
        → 즉, `~5 === -6` → `~x === -(x + 1)`이 성립!
        
        ### 🔍 수학적으로 보면
        
        - `~x`는 `x - 1`이 아니라 `(x + 1)`이야.
        - 왜냐면 비트를 뒤집는다는 건 **1의 보수**, 그리고 그걸 음수로 해석하려면 **+1을 더해서 2의 보수**로 바꿔야 하거든.
            
            ✅ 핵심 요약
            

| 표현 | 의미 |
| --- | --- |
| `~x` | x의 모든 비트를 반전 (1의 보수) |
| `-(x + 1)` | x의 2의 보수 표현 |
| `~x === -(x + 1)` | 자바스크립트에서 항상 성립함 |

### 문자열 ↔ 숫자

```jsx
var a = 42;
var b = a.toString();

var c = "3.14";
var d = +c;

b; // "42"
d; // 3.14
```

- `a.toString()` 은 겉보기에는 명시적이지만, 몇 가지 암시적인 요소가 감춰져 있음.
- 원시 값 42에는 `toString()` 메소드가 없으므로 엔진은 자동으로 42를 객체 래퍼로 ‘박싱’한다. ⇒ 말하자면 ‘명시적으로, 암시적인 작동(Explicitly Implicit)이다.

### 날짜 → 숫자

- `+` 단항 연산자는 ‘Date 객체 → 숫자’ 강제변환 용도로도 쓰인다. 결괏값이 날짜/시각 값을 유닉스 타임스탬프 표현형(1 January 1970 00:00:00 UTC 이후로 경과한 시간을 밀리 초 단위로 표시)

```sql
var d = new Date( "Mon, 18 Aug 2014 08:53:06 CDT" );
+d; // 1408369986000
```

- 현재 시각을 타임스탬프로 바꿀 때 관용적으로 사용하는 방법

```sql
var timestamp = +new Date();
```

- 강제변환 하지 않고 타임스탬프를 얻는 방법

```sql
var timestamp = new Date().getTime();
var timestamp = Date.now(); // ES5 에 추가된 정적 함수
```

## 암시적 변환

### 4.4.2 암시적 강제변환: 문자열 ↔ 숫자

- `[] + {}` vs `{}` + `[]`
    - 🧪 1. `[] + {}` → 결과: `"[object Object]"`
    
    🔍 해석 과정
    
    - `+` 연산자는 피연산자가 객체일 경우 **문자열로 변환**하려고 해.
    - `[]`는 빈 배열 → 문자열로 변환하면 `""`
    - `{}`는 빈 객체 → 문자열로 변환하면 `"[object Object]"`
    - 그래서 `"" + "[object Object]"` → `"[object Object]"`
    - 🧪 2. `{}` + `[]` → 결과: `0` 또는 `"0"` 또는 `"[]"`, 상황에 따라 다름
        - ⚠️ 주의: 이 표현은 **문맥에 따라 다르게 해석**
    - ▶️ 실행 위치에 따라 다르게 동작
        
        ```jsx
        {} + [] // 👉 결과: 0
        ```
        
    - 
        - 이건 자바스크립트가 `{}`를 **빈 블록으로 해석**하고, `+[]`만 남게 돼.
        - `+[]`는 배열을 숫자로 변환 → `0`
        - 그래서 최종 결과는 `0`
    - ▶️ 변수에 할당하거나 괄호로 감싸면 결과가 달라짐
        
        ```jsx
        let result = ({} + []); // 👉 결과: "[object Object]"
        ```
        
    - 
        - 여기서는 `{}`가 **객체 리터럴**로 해석됨
        - `{} + []` → `"[object Object]"`

## 4.5 느슨한/엄격한 동등 비교

- “==는 값의 동등함을, ===는 값과 타입의 모두의 동등함을 비교한다” 라고 오해한다.
- 그럴듯하지만 정확하진 않다. 엄청나게 많은 자바스크립트 책들에 그렇게 씌여있지만 불행하게도 다 틀렸다.
- **정확한 정의는, “동등함의 비교 시 ==는 강제변환을 허용하지만, ===는 강제변환을 허용하지 않는다."**

### 비교 성능

- 전자에 의하면 ===는 타입까지 체크하므로 == 에 비해 할 일이 많다. 반대로 후자에 따르면 오히려 타입이 다를 경우 강제변환을 해야 하므로 ==가 더 할일이 많다.
- 강제변환 시 처리 시간이 약간 더 소요되긴 하지만, 불과 몇 마이크로 초 단위의 차이일 뿐이다.
- 강제변환이 필요하다면 느슨한 동등 연산자(==)를, 필요하지 않다면 엄격한 동등 연산자를 사용하자

### 비교하기 : * → 불리언

```sql
var a = "42";
var b = true;

a == b; // false
```

1. Type(x)이 불리언이면 ToNumber(x) == y의 비교 결과를 반환한다.
2. Type(y)이 불리언이면 x == ToNumber(y)의 비교 결과를 반환한다.

```sql
var x = true;
var y = "42";
x == y; // false
```

앞으로 == true, == false 같은 코드를 쓰지 말자!

### 비교하기 : null → undefined

1. x가 null 이고, y가 undefined 면 true를 반환한다.
2. x가 undefined이고, y가 null이면 true를 반환한다.

null 과 undefined를 느슨한 동등 비교를 하면 서로에게 타입을 맞춘다.

```sql
var a = null;
var b;

a == b; // true
a == null; // true
b == null; // true
a == false; // false
b == false; // false
a == ""; // false
b == ""; // false
a == 0; // false
b == 0; // false
```

### 비교하기 : 객체 ⇒ 비객체

1. Type(x)가 String 또는 Number 고 Type(y)가 객체라면, x == ToPrimitive(y)의 비교 결과를 반환한다.
2. Type(x)가 Object이고 Type(y)가 String 또는 Number라면,ToPrimitive(x) == y 의 비교 결과를 반환한다.

```sql
var a = 42;
var b = [ 42 ];
a == b; //true

var a = "abc";
var b = Object( a );

a === b; // false
a == b; // true
```

항상 그런 것은 아님. == 알고리즘에서 더 우선하는 규칙 때문에 그렇지 않은 경우가 있다.

```sql
var a = null;
var b = Object( a ); 
a == b; // false

var c = undefined;
var d = Object( c );
c == d; // false

var e = NaN;
var f = Object( e );
e == f; // false
```

- null과 undefined는 객체 래퍼가 따로 없으므로 박싱할 수 없다. 그래서 Object(null)는 Object()로 해석되어 그냥 일반 객체가 만들어진다.
- NaN은 해당 객체 래퍼인 Number로 박싱되지만, == 를 만나 언박싱되면 결국 조건식은 NaN == NaN이 되어 결과는 false다.

### 4.6 추상 관계 비교

먼저 두 피연산자에 대해 ToPrimitive 강제변환을 실시하는 것으로 시작한다.

```sql
var a = [4, 2];
var b = [0, 4, 3];

a < b; // false
```

- a는 “4, 2”로 b는 “0, 4, 3”으로 문자열화시킨 후 앞 예제와 마찬가지로 어휘 비교를 한다.

```sql
var a = { b: 42 };
var b = { b: 43 };

a < b; // false
```

- a도 [object Object], b도 [object Object]로 변환되어 어휘적인 비교를 할 수 없음.

```sql
var a = { b: 42 };
var b = { b: 43 };

a < b; // false
a == b; // false
a > b; // false

a >= b; // true
a <= b; // true
```

- a ≤ b 는 실제로 a > b 의 평가 결과를 부정하도록 명세에 기술되어 있음.
